# Session Memory

> **How to maintain this file**
> Chronological session log, appended never rewritten. **This file is intentionally gitignored** — do not propose tracking it, and do not flag it as untracked when asked to update and commit.
> — Add an entry when the session produced at least one of: a commit that changes behaviour, a released version, a decision (even an unimplemented one), or a non-obvious finding that cost real time to reach. Skip it otherwise — answered questions, exploration that concluded nothing, and formatting-only commits do not earn one.
> — Lead each entry with a single verb-first line stating the outcome, then detail bullets beneath it. The tail should stay skimmable as a list of one-liners.
> — Keep the last 10 entries or ~250 lines, whichever comes first. **Delete** older entries rather than archiving them — anything durable should already have been promoted, and archiving hides it when promotion failed.
> — If something becomes stable project truth, move it to `.agents/handoff.md`. If it completes a milestone or creates a follow-up, record it in `docs/todo/ROADMAP.md`.
> — See `docs/process/PROJECT_MEMORY_MODEL.md`.
